**Gating wave:** 1

**Decision:** **Accept plan default — Routine connector if available by Phase 3, else Samson cross-post fallback.**

## Final resolution (2026-07-01) — Samson owns WhatsApp, Routines never call it

Superseded by live-run evidence: the first fired Routines (`daily-news-sweep`, `daily-solomon-standup`) hit "WhatsApp connector unavailable in this environment" — Routines run **remote** in Anthropic's cloud, where no WhatsApp connector exists. Rather than gate on Anthropic's connector roadmap, we commit now to the **fallback path as the permanent design** (Path A, cloud-native):

- **Routines dispatch to Slack only.** No Routine calls a WhatsApp connector, even if one later appears.
- **Samson `whatsapp_handler` (INT-01) is the single WhatsApp delivery path** — it subscribes to the relevant Slack channel's `chat.postMessage` event and cross-posts to the founder phone via Twilio.
- Rationale: single-sourcing cross-post in Samson removes the double-delivery risk and the remote/local ambiguity. Founder-phone reliability does not regress — it moves from the (nonexistent) Routine connector to the Samson adapter that INT-01 ships anyway for inbound `learn:`/`energy:`/`approve` parsing.

**Applied to `daily-news-sweep` (v1.1) on 2026-07-01.**

**`friday-energy-retro` (v2.0, 2026-07-01) — went Slack-native, NOT Samson-relay.** New evidence: Lionel reports he never received any energy-retro prompts. Root cause: section 5 called `connector: whatsapp`, but there is **no native WhatsApp connector** in claude.ai integrations (confirmed against `code.claude.com/docs/en/routines` — connectors are claude.ai MCP integrations; Slack/Linear/Gmail/Drive exist, WhatsApp does not). So it invoked a phantom connector and silently failed every Friday (connector failures surface only in the run transcript, never the green run-status). Rewritten to post to Slack `#solomon-checkin` with in-thread reply; the INT-01 Twilio parser + strict `energy:` format are retired (no proven consumer). This is a stronger form of the WhatsApp-retirement principle: the founder-phone WhatsApp surface is **unverified end-to-end** — worth confirming Samson's news-sweep cross-post actually lands before treating WhatsApp as load-bearing anywhere.

**Still pending:** `daily-solomon-standup` (paused). NOTE: its `SAMSON_INTERNAL_TOKEN missing` + `403 samson.highfunctioningsolutions.com` errors are **cloud-environment config fixes** (set the env var + add the host to the routine environment's Custom allowlist), not a pure Wave-14 backend gap — the remaining true dependency is whether Samson's cadence endpoints exist to be called.

## Resolution

1. **Primary path (preferred):** Native WhatsApp connector inside the Claude Code Routine.
   - Each affected Routine prompt instructs Claude to call the WhatsApp connector directly (post message, wait for reply via the energy-retro flow).
   - Samson sees the dispatched-to evidence in `output_artifacts.connector_calls` during ingestion.

2. **Fallback path (Phase 3 decision point):** If Anthropic has **not** shipped a WhatsApp connector by the start of Phase 3 (Wave 7, `ROUTINE-10`):
   - Routines post the digest to Slack only.
   - Samson `whatsapp_handler` cross-posts the Slack message body to Twilio WhatsApp Business API on receipt of the Slack message (via `chat.postMessage` event sub).
   - `INT-01` ships the Twilio adapter regardless (still needed for inbound `learn:`, `energy:`, `approve <id>`, `reject <id>` parsing).

## Decision deadline

`ROUTINE-10` (Wave 7) is the no-going-back checkpoint. Check Anthropic connector inventory before that wave fires; if WhatsApp connector is present, use primary path in `ROUTINE-02/03/06`. If absent, those Routine prompts get a 5-line edit to drop the WhatsApp connector call and Samson takes over.

## Why this matters

- WhatsApp delivery to the founder phone is the single most-load-bearing notification surface (per the research brief "the load-bearing ritual is the one that makes everything else compound"). Reliability cannot regress.
- The primary-then-fallback design means we don't *block* on Anthropic's connector roadmap — the Samson adapter ships in INT-01 anyway because of inbound message handling.
