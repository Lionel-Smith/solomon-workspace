## Token-budget breach behavior

Per plan section 1.5 success metric "Token budget breach days ≤ 5% of days":
- `cadence_token_snapshots` row at 23:55 NAS each day records actual vs budget.
- `budget_status` = `under` | `at` | `over`.
- Alert posted to `#cadence-status` on `over` (per OPS-02 Prometheus rule).
- Three consecutive `over` days for an agent triggers a re-budgeting prompt in the weekly meta-retro.

## Why this matters

The migration is the only place these values get baked into the DB. Changing them after BE-02 runs requires either a one-off UPDATE or a follow-up Alembic migration. Lock the values now.

## How to override

Edit the "Resolved budgets" table before BE-02 fires. The BE-02 session reads this file's table to compose the seed rows.

If budgets need post-migration tuning: a small `UPDATE cadence_agent_budgets SET daily_budget_usd = X WHERE agent_name = 'Y'` is acceptable — capture as a `/learn` so the change is auditable.
