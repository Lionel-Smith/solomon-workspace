# OQ-05: Eval Dataset Schema Specification

**Decision:** Operational Quality — Dataset Validation
**Status:** Accepted
**Date:** 2026-05-06
**Author:** Lionel + Solomon

## Context

The `friday-eval` Routine loads `cadence/eval/datasets/solomon-core-v1.yaml` on
every Friday run. If the dataset is malformed or incomplete, the Routine must
fail fast with a clear error rather than producing a corrupted pass-rate.

## Required Schema

Every entry in the `tasks` list must have ALL of the following fields:

| Field | Type | Description |
|-------|------|-------------|
| `task_id` | string | Unique identifier used in results table and Slack output |
| `description` | string | Prompt sent to the agent (and to the judge as `task_description`) |
| `agent_target` | string | One of: `solomon`, `bishop`, `jacob`, `esther`, `twins-cane`, `samson`, `clawdbot` |
| `expected_output` | string | Golden reference output used by the LLM-as-judge |
| `tolerance` | string | Criteria describing what variations are acceptable when scoring |
| `passing_threshold` | float | Score ≥ this value → `passed: true`. Default 0.7; may be higher for critical tasks |

Optional fields (do not fail validation if absent):

| Field | Type | Description |
|-------|------|-------------|
| `fixture_path` | string | Relative path from workspace root to a fixture file inlined at dispatch time |
| `tags` | list[str] | Metadata tags for filtering (not used by the Routine) |
| `notes` | string | Human-readable annotation (not sent to agent or judge) |

## Validation Rules

1. The `tasks` list must contain **exactly 10** items. More or fewer tasks invalidates drift comparison with prior weeks.
2. `agent_target` must be one of the 7 valid agents listed above. Unknown agents are treated as corrupted data.
3. `passing_threshold` must be a float in `[0.5, 1.0]`. Values outside this range indicate a data entry error.
4. `task_id` values must be unique within the dataset. Duplicate IDs corrupt the results table.
5. All required string fields must be non-empty after stripping whitespace.

## Failure Behavior

If validation fails for any reason, the `friday-eval` Routine dispatches the
following message to Slack `#dev-retro` and exits cleanly (no partial run):

```
**Friday Eval — Week {iso_week}** — Eval unavailable: dataset schema invalid.
See cadence/decisions/OQ-05.md for spec.
```

Samson's `eval_ingestion_handler` (BE-08) records this as a `status: failed`
run in `cadence_eval_runs` with `failure_reason: "dataset_schema_invalid"`.

## Dataset Versioning

- The dataset filename encodes its version: `solomon-core-v1.yaml`.
- Breaking changes (adding/removing tasks, changing `task_id` values) require
  a new version file (e.g., `solomon-core-v2.yaml`) and a Routine config update.
- Non-breaking changes (updating `expected_output`, `tolerance`, `notes`) may
  be made in-place; update `last_updated_at` in the YAML header.
- Drift comparison is only valid across runs of the same dataset version.
  When the Routine switches to a new version, the first run sets the new baseline
  (drift = null, "first eval — no prior week to compare").
