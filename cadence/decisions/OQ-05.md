## Resolved task set (v1)

Each task has `expected_output` + `tolerance` evaluated by Sonnet LLM-as-judge per Appendix C.4.1.

| # | Task ID | Description | Validates |
|---|---|---|---|
| 1 | `architecture_dispatch` | "Where does file-upload validation belong?" → expect three-layer answer pointing to controller | Constitution adherence |
| 2 | `quart_async_pattern` | "Generate a service method that fetches and updates a row" → expect explicit `await session.rollback()` on IntegrityError | Backend pattern conformance |
| 3 | `claude_md_audit` | Run audit on a synthetic CLAUDE.md with 2 redundancies + 1 contradiction | Audit accuracy |
| 4 | `learning_promotion` | Given 3 learnings about "always lint before commit", propose a CLAUDE.md addition | Retro promotion quality |
| 5 | `retrospective_kata` | Given 4 weeks of learnings, propose a Toyota Kata target condition | Retro framing |
| 6 | `jacob_anti_pattern` | Scan a file with 1 god module + 2 empty-except blocks | Anti-pattern detection |
| 7 | `bishop_test_writing` | Generate a pytest for a service method with 1 happy + 1 IntegrityError remap | Test quality |
| 8 | `esther_component_inventory` | Given a feature spec, list Shadcn components needed | FE specification quality |
| 9 | `twins_false_positive` | Given a benign code snippet flagged by Twins, classify and suppress | Security agent calibration |
| 10 | `samson_routing` | Given Slack message `/learn Quart Blueprint registration order`, produce the correct repository call | Cadence integration sanity |

## Storage

- Dataset YAML: `solomon-workspace/cadence/eval/datasets/solomon-core-v1.yaml`
- Judge prompt: `solomon-workspace/cadence/eval/prompts/judge.md` (see plan Appendix C.4.1)
- Both files created during `ROUTINE-05`.

## Why this matters

Drift detection depends on a stable baseline. Once `ROUTINE-05` runs the first eval, the dataset becomes the calibration reference for "did Solomon get worse this week?" Changing tasks mid-flight invalidates drift comparisons.

## Cost budget

Routine prompt caps cost at $5/run (per plan section 4.4). 10 tasks × ~$0.40 LLM-as-judge + agent-invocation = comfortably under cap.

## How to override

Edit the "Resolved task set" table to add/remove tasks before `ROUTINE-05` fires. Bumping task count above 15 will need re-budgeting the per-run cap.
